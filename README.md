# 房地產新聞 LINE 自動發文助理

給管理 100+ 個房地產相關 LINE 群組使用的新聞蒐集 + 自動發文系統。
系統會定期從新聞來源蒐集房地產相關新聞、依關鍵字自動分成 4 大類，
管理者在後台勾選要發布的新聞後，由 **4 個獨立的 LINE 官方帳號**
在設定的時間自動發到指定群組。

---

## 一、新聞蒐集的 4 大方向

| 代碼 | 分類 | 範圍 | 對應頻道 |
|---|---|---|---|
| A | 土地利用相關 | 都市計畫變更、產業園區、工廠立體化等政府法規 | 土地法規小助理 |
| B | 建築營造相關 | 建設、代銷、房仲、包租代管、法拍等市場觀察 | 建築市場小助理 |
| C | 房地產應用相關 | AI 應用、ESG、綠建築、綠建材等 | 房地產科技小助理 |
| D | 其他房地產相關 | 法規、稅務、政策、補助等市場新聞 | 稅務政策小助理 |

分類定義與關鍵字集中在 `src/config/categories.js`，可依實際新聞用語隨時增減。
新聞來源清單在 `src/config/sources.js`（RSS 為主），分類邏輯在
`src/news/classifier.js`：

1. 對每篇新聞的標題＋摘要，逐分類計算關鍵字命中次數。
2. 命中最多次的分類勝出，並附上信心分數（命中次數）。
3. 若所有分類都是 0 分，退回該新聞來源預設的分類；仍無法判斷則歸類到 D，
   等待人工在後台複核、手動改分類。

> **重要提醒**：`sources.js` 內目前列的是幾個常見的內政部／房地產新聞網 RSS
> 網址，僅作為起點。實際部署時請逐一確認網址是否仍然有效（新聞網站常改版），
> 也建議加入貴公司/聯盟現有的新聞來源。系統對抓取失敗的來源會直接跳過並記
> 錄錯誤，不會讓整個排程掛掉。

### 新聞如何被抓進系統

- 排程（或手動按下後台「立即抓新聞」）呼叫 `src/news/fetcher.js`
- 逐一讀取 `sources.js` 內的 RSS，解析後做分類，用「連結網址」算出唯一
  ID 避免重複
- 寫入 `data/db.json` 的 `news` 陣列，狀態預設為 `pending`（尚未勾選）

## 二、4 個 LINE 助理的設計

### 為什麼是 4 個帳號，而不是 1 個帳號管全部群組？

1. **推播用量分開算**：LINE Messaging API 的每月推播則數是以「頻道」計算，
   100+ 群組如果全部塞進同一頻道，很容易撞到用量上限，也難以只針對某類
   新聞控管發送量。
2. **群組可以自由訂閱主題**：例如某些房仲群組只想收「法拍/市場」新聞
   （頻道 B），不想收「土地法規」（頻道 A），拆開後由群組管理員自行決定
   要邀請哪幾個機器人加入，不需要在同一帳號裡做訊息篩選。
3. **故障隔離**：任一頻道 Token 過期或被停權，只影響該分類的發文，其他
   3 個分類仍正常運作。

### 4 個助理

| 頻道代碼 | 預設名稱 | 對應分類 |
|---|---|---|
| A | 土地法規小助理 | A. 土地利用相關 |
| B | 建築市場小助理 | B. 建築營造相關 |
| C | 房地產科技小助理 | C. 房地產應用相關 |
| D | 稅務政策小助理 | D. 其他（法規/稅務/政策/補助） |

每個頻道各自對應一組 LINE Developers 的 Channel access token / Channel
secret（見 `.env.example`），互不相干。

### 後台可以做什麼

打開 `public/index.html`（伺服器啟動後即 `http://localhost:3000`）：

1. **上方分類頁籤**：切換看 A/B/C/D 或全部新聞。
2. **新聞卡片**：每則新聞下方有 4 個核取方塊（推 A / 推 B / 推 C / 推 D），
   同一則新聞也可以同時勾給多個頻道（例如同時符合建築與稅務時事）。
   勾選後新聞狀態自動變成「已勾選待發」。
3. **右側 4 張頻道卡片**：
   - 開關「啟用每日自動發文」
   - 設定每天固定發文時間（例如 A 頻道 09:00、B 頻道 09:30…錯開避免洗版）
   - 貼上該頻道要發送的目標群組 ID（一行一個）
   - 「立即依目前勾選發送」：不等排程，馬上把目前勾選好、狀態為
     「已勾選待發」的新聞發到目標群組，方便測試

### 怎麼取得 100+ 個群組的群組 ID？

LINE 官方帳號沒有主動列出「我在哪些群組」的 API，因此系統用 Webhook
自動記錄：

1. 把對應分類的機器人加入群組後，系統會在後台「已知群組」清單自動記下
   `groupId`（`join` 事件）。
2. 也可以在群組內 @機器人 輸入「群組ID」，機器人會回覆目前群組的 ID，
   方便核對。
3. 管理者從「已知群組」清單複製需要的 ID，貼進右側對應頻道的「目標群組」
   欄位再儲存。

### 發文格式

系統用 LINE Flex Message 排版每則新聞（標題、摘要、來源、「閱讀全文」按
鈕），比純文字更適合被群組快速略過或點入閱讀，且不會像一般連結分享一樣
每次樣式不一致，見 `src/line/client.js` 的 `buildFlexMessage`。

## 四、安裝與啟動

```bash
npm install
cp .env.example .env
# 編輯 .env，填入 4 個 LINE 頻道各自的 Channel access token / Channel secret
npm start
```

啟動後：

- 後台網頁：`http://localhost:3000`
- 健康檢查：`GET /healthz`
- 4 個頻道各自的 Webhook：`POST /webhook/A`、`/webhook/B`、`/webhook/C`、`/webhook/D`
  （需在 LINE Developers Console 的 Messaging API 設定頁填入對外可存取的網址，
  例如 `https://your-domain.com/webhook/A`）

### 保護後台 API

`.env` 中的 `ADMIN_TOKEN` 用來保護 `/api/*`，前端會把它存在瀏覽器
localStorage，之後每次呼叫 API 都會帶 `Authorization: Bearer <token>`。
正式上線務必設定一組夠長的隨機字串，並透過 HTTPS 提供服務。

### 定期抓新聞

`fetcher.js` 可獨立執行：

```bash
npm run fetch:news
```

建議用系統排程（cron、GitHub Actions、雲端排程器等）每 30–60 分鐘打一次
`POST /api/news/fetch`，或直接排程執行 `npm run fetch:news`。

## 五、使用教學（操作流程）

### 第一次設定（一次性）

1. **把程式部署到一台有公開網址的主機**
   LINE 需要能連到你的伺服器才能送 Webhook 事件過來，所以不能只在自己
   電腦跑（除非用 ngrok 之類的工具暫時對外開放測試）。可以放
   Render、Railway、自家 VM 等，只要能跑 Node.js 並開一個對外的網址
   （建議用 HTTPS）。

2. **申請 4 個 LINE Official Account**
   到 [LINE Official Account Manager](https://manager.line.biz/) 各自申請
   帳號（或用既有的 4 個帳號），再到
   [LINE Developers Console](https://developers.line.biz/console/) 把每個
   帳號串成 Messaging API Channel，各自取得：
   - Channel access token
   - Channel secret

3. **填入設定檔**
   ```bash
   git clone <你的 repo> && cd House
   npm install
   cp .env.example .env
   ```
   打開 `.env`，把 4 組 token/secret 分別填到 `LINE_BOT_A_...`、
   `LINE_BOT_B_...`、`LINE_BOT_C_...`、`LINE_BOT_D_...`，並設定一組
   `ADMIN_TOKEN`（自己想一組夠長的密碼，保護後台）。

4. **啟動伺服器**
   ```bash
   npm start
   ```
   會看到 `http://localhost:3000` 啟動訊息（正式上線後就是你部署的網址）。

5. **到 LINE Developers Console 設定 Webhook URL**
   每個頻道各自填：
   ```
   https://你的網域/webhook/A
   https://你的網域/webhook/B
   https://你的網域/webhook/C
   https://你的網域/webhook/D
   ```
   記得在 Console 把「Use webhook」打開。

6. **把機器人加進群組、取得群組 ID**
   - 把對應分類的機器人邀請進相關的房地產群組（例如只想收法拍/房仲新聞
     的群組，就只加「建築市場小助理」）。
   - 加入後系統會自動記下 `groupId`，顯示在後台右側「已知群組」清單。
   - 也可以在群組裡 @機器人 打「群組ID」三個字，機器人會直接回覆給你
     複製。

### 日常操作

1. **打開後台**：瀏覽器開你的網域（或本機 `http://localhost:3000`），
   第一次要在右上角貼上 `.env` 設定的 `ADMIN_TOKEN` 並按「儲存」。
2. **抓新聞**：按右上角「立即抓新聞」，系統會去抓 RSS 來源、自動分成
   A/B/C/D 四類。也可以設定外部排程定期打 `POST /api/news/fetch`，不用
   每次手動按。
3. **瀏覽並勾選要發的新聞**：上方頁籤切換看各分類新聞，每則新聞卡片下方
   有 4 個核取方塊（推 A / 推 B / 推 C / 推 D），勾選要發到哪個頻道（一則
   新聞也可以同時勾多個）。
4. **設定發文時間與目標群組**：右側 4 張頻道卡片，各自打開「啟用每日自動
   發文」、設定每天固定發文時間（建議錯開，例如 09:00、09:30、10:00、
   10:30）、貼上目標群組 ID（一行一個），按「儲存設定」。
5. **測試**：先不開自動排程，直接按「立即依目前勾選發送」，確認訊息真的
   會發到指定群組、格式正確，沒問題後再打開「啟用每日自動發文」讓它照表
   操課。

之後每天只要做步驟 2、3（抓新聞、勾選新聞），排程會自動在設定的時間把
勾選好的新聞發出去。

```

    webhook.js          # 4 個頻道各自的 Webhook（記錄群組 ID）
  scheduler/
    index.js            # node-cron 排程，依 4 個頻道各自的時間發文
  routes/
    news.js              # 新聞查詢／勾選／改分類 API
    schedule.js            # 排程與群組設定 API
  store/
    db.js                  # 簡易 JSON 檔案資料庫
  server.js                # Express 進入點
public/                     # 後台管理網頁（純 HTML/CSS/JS，無框架）
data/db.json                 # 執行期資料（新聞、排程設定、發文紀錄）
```

## 七、工業廠房案件媒合社群（`/matching`）

除了新聞發文助理，本專案同時內建一套給工業廠房經紀同事使用的**案件媒合社群**，
用來解決買方客需與同事手上案件之間「互相不了解、資訊零散」的問題。伺服器啟動後
開啟 `http://localhost:3000/matching`（首頁右上角也有連結）即可使用。

### 核心功能

| 功能 | 說明 |
|---|---|
| 案件牆 | 建立/編輯案件：地址、面積、開價、**產權確認狀態**（已確認／確認中／有糾紛）、**現況**（使用中／閒置／查封）、帶看紀錄 |
| 權限設定 | 每個案件可設「私人（僅自己＋指定同事）」或「團隊共享」，並可針對個別同事設定「可檢視／可編輯」，由案件建立者或系統管理者維護 |
| 案件專屬討論區 | 每個案件底下都有留言區，方便同事針對產權、帶看細節、現況等互相討論、留紀錄 |
| 客需媒合牆 | 買方經紀張貼買方客需（地區/類型/坪數/預算），其他同事可推薦手上案件；客需張貼者可接受／婉拒推薦，接受後系統會自動授予該案件檢視權限 |
| 實價合理性分析 | 依優先序嘗試三種資料來源：① `PRICE_AI_ENDPOINT` 自訂/第三方實價 AI 服務 ② 內政部「實價登錄」官方開放資料（`GOV_PRICE_REGISTRY_ENABLED=true`） ③ 都沒有或查不到時，退回系統內「同地區＋同類型」案件與手動輸入比較案例試算（詳見下方「實價登錄開放資料串接」） |
| 買方銷售簡報 | 依案件資料自動整理成可列印/匯出 PDF 的簡報頁（`presentation.html`），給買方經紀直接帶去談 |
| 賣方議價報告書 | 整合實價分析、議價優勢／風險、帶看回饋，產出可列印的專業報告書（`negotiation-report.html`），輔助賣方經紀議價 |
| 意見回饋 | 任何登入的同事都能點畫面右下角「💬 意見回饋」針對目前頁面留下評分／文字意見；管理者在「意見回饋」頁籤彙整查看、標記已處理，方便收集同事實際試用的反饋 |

### 帳號與權限模型

- 這個模組使用**每位使用者各自的存取權杖**（不同於新聞系統的單一 `ADMIN_TOKEN`），
  才能做到「誰能看、誰能編輯」的精細權限控管。
- 系統第一次啟動時會自動建立一組管理者帳號，權杖會印在伺服器的 console 記錄中
  （也可在 `.env` 用 `MATCHING_ADMIN_TOKEN` 固定）。
- 管理者登入後，於「成員與權限」頁籤新增同事帳號，系統會產生一次性顯示的權杖，
  交給本人貼到登入畫面即可使用。
- 案件層級的檢視／編輯權限則在**案件詳情頁**由建立者或管理者個別設定。

### 實價登錄開放資料串接

`GOV_PRICE_REGISTRY_ENABLED=true` 時，實價分析會改抓內政部「不動產成交案件
實際資訊資料供應系統」的官方開放資料（`src/matching/priceEngine/govOpenData.js`）：

- 官方沒有「輸入地址查一筆」的即時 API，只提供整包批次 CSV（全國、每 10 天
  更新一次，`GOV_PRICE_REGISTRY_URL` 預設抓「本期」不動產買賣批次資料的
  ZIP）。系統會依案件地區判斷縣市代碼、解壓對應縣市的 CSV，篩出「廠房／
  工業用」且同鄉鎮市區的案例來試算單價區間，下載結果會快取
  `GOV_PRICE_REGISTRY_CACHE_HOURS` 小時（預設 12）避免每次查價都重新下載整包。
- 下載或解析失敗（連不上、官方格式異動等）會自動退回內部比較案例試算，
  並在伺服器 log 印出警告，不會讓 API 掛掉。
- **重要**：這個功能在本專案的開發環境中，因網路政策封鎖了
  `plvr.land.moi.gov.tw`，只能用模擬資料驗證 CSV／ZIP 解析邏輯本身，
  無法實際連線測試下載。正式部署（能連上內政部網站）啟用前，請先手動打一次
  `GET /api/matching/cases/:id/price-analysis` 確認 `source` 回傳
  `gov-open-data` 且資料合理，而不是預期外一直退回 `local-estimate`。

### 找同事測試（UAT）

功能都做完後，最實際的下一步是找 1-2 位真的會用到這套系統的同事（買方經紀／
賣方經紀）實際操作一輪，而不是只有自己空想。建議流程：

1. **管理者先建帳號**：登入後到「成員與權限」頁籤，幫每位測試同事各建一組帳號，
   把系統顯示的一次性權杖傳給本人（例如用內部通訊軟體私訊，不要用公開頻道）。
2. **請同事照著這個腳本試一輪**（大約 10-15 分鐘）：
   - 貼上權杖登入
   - 建立一筆自己手上正在跑的真實案件（或先用假資料），把產權狀態、現況填清楚
   - 新增一次帶看紀錄、一筆比較案例（附近類似案件的成交/開價）
   - 按「執行分析」看實價合理性分析的結果是否合理、看得懂
   - 在案件討論區留言，測試同事之間能不能互相看到、討論
   - 到「客需媒合」貼一個假設的買方需求，或反過來推薦一個案件給別人貼的客需，
     並實際按「接受」測試權限是否有正確授予
   - 打開「買方銷售簡報」「賣方議價報告書」，檢查排版跟內容是否是他們平常會
     想拿去用的樣子
3. **邊測邊按右下角「💬 意見回饋」**：不用等測完全部才反饋，卡住、看不懂、
   覺得少了什麼，隨手留言即可（可選填 1-5 分評分＋文字說明，哪個畫面都可以）。
4. **管理者到「意見回饋」頁籤彙整**：只有管理者看得到這個頁籤，可以看到每則
   回饋來自誰、針對哪個畫面、幾分，處理完可以標記「已處理」方便追蹤進度。

### 目錄結構

```
src/matching/
  store.js          # 獨立的 JSON 檔案資料庫（data/matching-db.json）
  auth.js           # 權杖驗證、角色與案件權限判斷
  priceEngine/       # 實價分析轉接層
    index.js          # 依序嘗試 PRICE_AI_ENDPOINT → 實價登錄開放資料 → 本地試算
    govOpenData.js     # 內政部實價登錄開放資料下載/解析/篩選
  routes/            # 使用者、案件、討論區、客需媒合、實價分析、簡報/報告書、意見回饋
public/matching/
  index.html/app.js/style.css   # 主要操作介面（案件牆／客需媒合／權限管理）
  presentation.html              # 買方銷售簡報（可列印）
  negotiation-report.html         # 賣方議價報告書（可列印）
```

> 目前資料庫同樣是單一 JSON 檔，設計上與新聞系統一致；正式多人上線建議參考
> 下方「可以延伸的方向」，換成正式資料庫並加上真正的登入（目前為權杖登入，
> 適合小型內部團隊）。

## 八、可以延伸的方向

- 目前的資料庫是單一 JSON 檔，適合單機/小規模使用；群組與新聞量再擴大，
  建議換成 PostgreSQL/SQLite，只需替換 `store/db.js` 的實作。
- 目前的自動分類只用關鍵字比對，可以之後接上 LLM 做語意分類與自動摘要，
  取代目前 300 字截斷摘要。
- 目前群組設定是「一個頻道對多個群組」統一發同樣的新聞；若要做到「某些
  群組只要某類新聞裡的一部分」，可以在 `schedules` 內把 `groupIds`
  換成「群組 → 訂閱分類/關鍵字」的對照表。
